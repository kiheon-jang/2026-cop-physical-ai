🤖 AI 자동화 운영 방법

수동 개입 없이 자율 운영되는 구조 — 로컬 Mac Mini 에서 Hermes AI 에이전트가 정해진 시각에 시뮬·테스트·보고를 자동 실행합니다.

이 프로젝트는 수동 개입 없이 자율적으로 운영됩니다. 로컬 Mac Mini 가 24시간 가동되며, Hermes Agent (AI 에이전트)가 하루 4번 정해진 시각에 시뮬 환경 구축 · 테스트 · 보고서 작성 · 메일 발송까지 수행합니다. CoP 담당자는 의사결정과 외부 의존 (부품 구매 · 3D 프린팅) 해결만 담당합니다.

🎓 CoP 리뷰

사용 기술, 학습 방법, 의사결정 근거를 한 페이지에 정리했습니다.

정비현장의 PCB 작업을 로봇에 가르치는 프로젝트입니다. 가상 환경(시뮬)에서 200번 시연 데이터를 자동으로 만들고 → AI가 그 시연을 흉내내는 법을 학습하고 → 학습된 모델을 실제 로봇팔에 옮기는 흐름입니다.

전체 흐름 (6 단계)

—

사용 기술 — 무엇을, 왜, 어떻게

5가지 핵심

MuJoCo 3.8

가상 로봇팔 시뮬 엔진 Apache 2.0
왜 선택?

처음엔 NVIDIA Isaac Lab 검토 → Mac Mini (Apple Silicon ARM64) 미지원으로 불가 판정 (2026-05-01 결정 변경). MuJoCo 는 Apple Silicon 네이티브 + pip install mujoco 한 줄 설치 + Apache 2.0 오픈소스. 학습 알고리즘 검증에 충분히 가벼움.

어떻게 사용?

SO-ARM101 MJCF 모델을 import → 헤드리스 렌더링으로 천장 카메라 영상 + 6축 관절 상태 수집. sim_pick_place.py 가 IK(역기구학) 로 큐브 위치 잡고 Pick-Place 동작 자동 생성. sim_data_collector.py 가 큐브 위치 ±20mm 랜덤 변동으로 200 에피소드 합성.

SO-ARM101

오픈소스 6-DoF 로봇팔 CC-BY-SA
왜 선택?

TheRobotStudio 오픈소스 (BOM·STL·MJCF 공개) + HuggingFace LeRobot 공식 지원. 가격 적당 (≈ $500/대) 하고 Leader + Follower 페어로 사람이 직접 시연 (텔레오퍼레이션) 도 가능. 차후 PCB 작업처럼 정밀 시연이 필요할 때 데이터 수집 옵션 확보됨.

어떻게 사용?

MJCF 모델 (so101_new_calib.xml) 로 시뮬과 실기 동일 캘리브레이션 유지. 6 관절: shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper. 실기 서보는 Feetech STS3215 (12V/7.4V) — 7월부터 실기 검증 (Phase 2).

HuggingFace LeRobot

로봇 학습 프레임워크 Apache 2.0
왜 선택?

데이터 포맷 (LeRobot Dataset) + 학습 알고리즘 (ACT / Diffusion Policy / π0) + 추론까지 end-to-end. 산업/연구 표준화 중. SO-ARM101 공식 지원, HuggingFace Hub 데이터셋 공유 가능 (선택). 자체 구현 대비 검증된 코드베이스.

어떻게 사용?

200 에피소드 데이터를 LeRobot Dataset v3.0 포맷 (local/cop-pickplace, root=data/episodes/) 로 저장. parquet (관절 상태) + mp4 (카메라 영상) 분리 저장. 이 데이터셋이 그대로 ACT 학습 입력.

ACT

Action Chunking Transformer (모방학습) 2023, MIT
왜 선택?

Diffusion Policy (DP) 대비 가볍고 빠름 → 1차 학습 적합. 트랜스포머가 다음 100 프레임 액션 묶음을 한 번에 예측 → 시간적 일관성 있는 동작 생성. Mac Mini 에서 학습 가능. DP 비교는 9월 (Phase 4) 예정.

어떻게 사용?

scripts/train_act.py 가 LeRobot 의 ACTConfig + ACTPolicy 호출. 입력 = 천장 카메라 + 6축 관절 (관측 n_obs_steps 과거 프레임). 출력 = 6축 액션 시퀀스 (chunk_size=100 미래 프레임). epoch 100, batch 8, 백그라운드 학습. 2026-06-15 (W3) 시작 예정.

모방학습 (Imitation Learning)

학습 방식 — "보고 따라하기"
왜 선택?

강화학습 (Reinforcement Learning) 은 시행착오로 학습 → 실기 로봇 파손 위험 + 데이터 효율 낮음. PCB 작업처럼 "정확한 시연이 가능한" 작업은 모방학습이 적합. 시연 데이터 200건이면 1차 알고리즘 검증 충분.

어떻게 사용?

시뮬 IK 가 "정답" 액션을 자동 생성 → 그 액션과 동시 카메라 관측을 짝지어 200 에피소드 저장 → ACT 모델이 "이 영상이 보일 때 이렇게 움직여라" 매핑 학습. 차년도 (Phase 3+) 에 강화학습 추가하여 시뮬에 없는 상황 대응력 보강 예정.

현재 학습 데이터셋

Phase 1 W1-2 진행 증거

AI 학습 1 사이클 — 어떻게 흉내내는가

관측 → 모델 → 액션 → 반복
Step 1 — 관측
Input: 영상 + 관절 위치

천장 카메라 RGB 영상 (480×640) + 현재 6축 관절 위치 (qpos). 과거 n_obs_steps 프레임 분량 묶음.

Step 2 — ACT 모델
Transformer 추론

관측을 임베딩 → 트랜스포머 인코더-디코더 → "이 영상에서 다음 100 프레임 어떻게 움직일까?" 예측.

Step 3 — 액션
Output: 6축 액션 시퀀스

다음 chunk_size 프레임의 6축 ctrl 명령. 시뮬에서는 MuJoCo actuator 에 전달, 실기에서는 STS3215 서보에 전달.

Step 4 — 실행
로봇이 액션 실행

로봇이 액션을 실행 → 새 관측 (영상 + 관절 변화) → Step 1 로 돌아가 반복. 큐브가 그리퍼 안에 잡힐 때까지.

왜 이렇게 진행하나 — 의사결정 근거

  • 왜 시뮬 합성 데이터? 실기 로봇 24시간 가동 비용 큼. 시뮬은 일주일에 수백 에피소드 자동 합성 가능 → 데이터 비용 ↓, 알고리즘 검증 가속. 7월부터 실기 텔레오퍼레이션 데이터 추가 예정.
  • 왜 MuJoCo (Isaac Lab 아님)? Mac Mini (Apple Silicon ARM64) 에서 Isaac Lab 미지원 (2026-05-01 결정 변경). MuJoCo 는 네이티브 + 즉시 설치. Isaac Lab 은 차년도 GPU 서버 도입 시 RL 학습용으로 전환.
  • 왜 텔레오퍼 안 함 (시뮬만)? 사람 시연은 정확하지만 시간/노동 비용 큼. IK 기반 시뮬 합성으로 빠르게 200ep 확보 → 1차 학습. 시뮬에 없는 변수 (조명, 마찰, 노이즈) 는 Domain Randomization 으로 보강.
  • 왜 ACT (Diffusion Policy 아님)? DP 보다 가볍고 빠름 → Mac Mini 에서 학습 가능. 트랜스포머가 시간 일관성 있는 chunk 단위 액션 예측 → 안정적. 정확도 부족 시 9월 (Phase 4) 에 DP 비교/전환.
  • 왜 Pick-Place 부터? 가장 단순한 정밀 작업. 성공하면 PCB 부품 픽업 → RS232 결선 (HHT 단자 꽂기) 까지 단계 확장. 정비현장 핵심 반복 작업 자동화가 최종 목표.
  • 왜 Sim-to-Real 단계 분리? 시뮬 학습 결과를 실기에 옮길 때 "현실 격차" (Sim-to-Real gap) 존재. 7월 (Phase 2) 에 시뮬 모델을 실기 50 에피소드로 측정 → 격차 식별 → Domain Randomization / Fine-tuning 으로 좁힘.

차년도 (Phase 3+) 계획

2027~

강화학습 도입 — 모방학습으로 부족한 상황 대응력을 RL 로 보강. Isaac Lab + LeIsaac (NVIDIA) 로 전환, GPU 병렬 환경으로 대규모 학습. 인프라: AWS g5.2xlarge (≈ $1.21/hr) 또는 별도 GPU 서버.

GR00T N1.5 파인튜닝 — NVIDIA 의 VLA (Vision-Language-Action) 모델. 시뮬 데이터 → GR00T 파인튜닝 → 실기 배포 파이프라인. --no-tune_diffusion_model 플래그로 24GB VRAM 절약.

최종 배포 타겟 — NVIDIA Orin Nano Super (학습 불가, 추론 전용). 학습된 정책을 ONNX/TensorRT 로 최적화 → 임베디드 배포.

확장 옵션 — LeKiwi (이동체 매니퓰레이터) 또는 XLeRobot (확장형 모바일 로봇). PCB 작업 자동화 성공 시 정비현장 내 이동 작업으로 확장.

시각자료

시뮬 환경에서 만들어진 움직임 + 학습 데이터셋 + 실제 하드웨어. 지금까지 만들어진 것들.

시뮬 동작 영상

학습 전 단계 · IK 기반 시나리오

지금 보고 있는 영상이 어떤 단계인지

학습 전 단계의 시각자료입니다. 시뮬 영상은 휴리스틱(IK · 역기구학) 기반 시나리오 동작이며, AI 모델이 학습한 결과가 아닙니다. 영상에서 큐브를 정확히 집지 못하는 모습이 보일 수 있는데, 이는 오류가 아니라 학습 전 정상 상태입니다.

현재까지 한 일: 시뮬 환경 셋업 완료 (Phase 0) · 200 에피소드 / 12,400 프레임 학습 데이터셋 합성 완료 (Phase 1 W1-2). 위 데이터셋 영상이 학습에 그대로 들어갑니다.

다음 단계 (실제 학습): 2026-06-15 부터 ACT 학습 시작 (Phase 1 W3). 학습이 완료되면 모델의 inference 결과 영상이 별도로 추가될 예정입니다. 7월부터는 실제 로봇팔로 검증 (Phase 2).

6개월 여정

실기 없이 학습할 수 있는 환경 구축 → 10월 1차 기능 완성. 각 단계의 비즈니스 결과와 주차별 진행률.

한 줄 요약

MuJoCo 시뮬 환경에서 SO-ARM101 로봇팔의 모방학습(ACT/DP) 을 단계적으로 구축해 PCB 픽앤플레이스 시연(2026-10) 까지 가는 6개월 프로젝트의 진척 대시보드.

매일 자동으로 시뮬 작업이 진행되고 (research/simulation/), 테스트 결과가 누적되며 (research-log/), 월말 보고서용 증거가 정리됩니다 (report-evidence/). 이 사이트는 그 누적된 진척을 한 페이지에서 보고, 검색하고, 외부 의존 항목과 다음 단계를 점검하는 도구입니다.

왜 만들었나

  • 가시성: Phase 0~5, 6개월(180+ 시뮬 작업) 의 진척을 한눈에 — 폴더 트리로는 안 보임
  • 의존 추적: 실기팀/외부 머신/사용자 수동 처리 항목을 마감일·담당자별로 → "왜 진행이 멈췄나" 즉시 확인
  • 증거 큐레이션: 일일 진척에서 보고용 증거 후보를 자동 추출 → 월말 보고서 작성 시간 절약
