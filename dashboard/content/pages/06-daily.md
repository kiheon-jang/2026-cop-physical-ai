## 기능명세

활동 타임라인 화면(`view-daily`)은 날짜별로 시뮬 작업, 커밋, 자동 복구(self-heal)를 통합해 시간 역순으로 표시하는 화면이다. 매일 23:30 cron 이후 자동 갱신된다.

**헤더**
제목: "활동 타임라인". 부제(`daily-sub`): "날짜별 시뮬 작업 · 커밋 · 자동 복구 통합. 매일 23:30 자동 갱신." (JavaScript가 최근 업데이트 날짜를 보강할 수 있음)

**타임라인 목록 (timeline-list)**
`build_activity_timeline(daily, sim_tasks, days=60)`이 반환한 배열에서 날짜별 그룹 카드를 생성. 최근 60일, 날짜 역순 정렬.

각 날짜 그룹 카드에 포함되는 정보:
- **날짜 + 요일**: `date` (YYYY-MM-DD)
- **활동 카테고리 태그**: commit 메시지의 `[태그]` 패턴에서 추출한 분류 (시뮬 작업, 테스트·메트릭, 문서 갱신, 주간 정리, 보고, 데이터 수집, 학습, 아키텍처 결정, 자가치유)
- **커밋 수**: `commit_count` (학습 본질 태그가 있는 커밋만 집계)
- **자가치유 발생 수**: `self_heal_count` (heal 점 표시)
- **커밋 목록**: 최대 8개 메시지 (sha 포함)
- **시뮬 작업 제목**: 해당 날짜의 `research/simulation/*.md` 파일 제목 최대 3개
- **phase 레이블**: 해당 날의 `agent/research-log/*.md`에서 추출한 "오늘 진행 단계"
- **실행 스크립트**: 해당 날의 `research-log`에서 `### 스크립트:` 패턴으로 추출한 스크립트 목록(최대 5개)
- **자가치유 액션**: `[자가치유]` 마커로 추출한 복구 내용(최대 3개)

**활동 필터링 로직**
- git log에서 `[태그]` 가 CORE_ACTIVITY_TAGS(`시뮬`, `로그`, `히스토리`, `주간정리`, `데이터`, `학습`, `테스트`, `보고서`, `결정`, `메일`) 중 하나로 시작해야 활동으로 집계.
- `self-heal`/`자가치유` 포함 커밋은 별도 self_heal_count로 집계.
- 학습 본질 커밋이 0건이어도 sim_task 또는 self-heal이 있는 날은 타임라인에 포함.

**데이터 출처**: git log (최근 60일), `agent/research-log/*.md`, `research/simulation/*.md`.

**상호작용**
- 날짜 카드 클릭: 없음 (카드 형태는 확장 없이 목록만 표시).
- 페이지는 정적 목록. WebSocket으로 23:30 이후 자동 갱신.

## 사용가이드

활동 타임라인은 "어제, 그제, 지난주에 무슨 작업이 진행됐는지"를 날짜별로 확인하는 화면입니다.

**화면 구성**
날짜별 카드가 최신 날짜부터 위에서 아래로 나열됩니다. 각 카드에는 그날의 주요 활동, 시뮬 작업 제목, 실행된 스크립트, 자동 복구 발생 여부가 표시됩니다.

**카테고리 태그**
각 날짜 카드의 상단 태그(예: "시뮬 작업", "테스트·메트릭")는 그날 어떤 종류의 작업이 진행됐는지 보여줍니다. 대시보드 관련 작업이나 설정 변경은 이 태그에 나타나지 않고, 실제 로봇 학습과 관련된 작업만 표시됩니다.

**자가치유 표시**
"자가치유(self-heal)"는 에이전트가 오류를 만났을 때 자동으로 복구를 시도한 기록입니다. 빨간 점 또는 heal 표시로 나타나며, 발생 횟수가 많아도 다음 cron에서 자동 재시도하므로 직접 조치가 필요한 경우는 드뭅니다.

**언제 활용하나요?**
- 보고서 작성 시: "지난 주에 어떤 작업이 있었나" 확인
- 이슈 추적 시: "특정 날에 자가치유가 여러 번 발생했다면 뭔가 막힌 게 있다"
- 진척 확인 시: 연속으로 활동 카드가 있으면 순조롭게 진행 중

**자동 갱신**
매일 밤 23시 30분 자동 작업이 끝나면 이 화면의 데이터도 새로 갱신됩니다. 브라우저를 열어두면 새로고침 없이 자동으로 업데이트됩니다.
