# 시뮬 grasp task 근본 원인 규명 + 정상화 계획 (2026-06-22)

> sandbox 블로커(6/7~21, 14일) 해소 후 파이프라인 전 구간을 **처음으로 실제 실행**한 결과.
> 그동안 코드는 작성됐으나 0회 실행이라 드러나지 않았던 결함들을 측정으로 규명.

## 1. 파이프라인 가동 검증 (성과)

데이터 합성 → ACT 학습 → 추론 rollout → Pick 성공률 측정, **전 구간이 실제로 돈다**는 것을 확인.
- 학습: smoke 통과 → 100 epoch MPS 학습, loss 22 → 0.0016 단조 수렴 (`scripts/train_act.py`)
- 추론/측정: `scripts/render_act_rollout.py` 신규 — 학습 모델을 시뮬에서 rollout, 영상 렌더 + 성공률 측정

## 2. 규명된 근본 결함

### (a) 데이터 수집 expert가 큐브를 한 번도 안 잡음
`sim_data_collector.py` 의 `PICK_PLACE_POSES` 는 **고정 관절 각도** 시퀀스로, 큐브 위치와 무관하게
항상 동일 동작. 측정:
- 중앙 큐브(0.15,0,0.025)에서도 그리퍼가 큐브에 **52.7mm 못 미침**, 큐브 들림 0.8mm.
- → 200 에피소드 학습 데이터 **전부가 "허공 헛손질"**, 성공 시연 0개.
- → 그걸 학습한 ACT 모델의 rollout 성공률 **0/5** (당연한 결과. loss 0.002 ≠ task 성공).

### (b) 그리퍼/큐브 공차가 사실상 그립 불가
| | 값 |
|---|---|
| 큐브 한 변 | 50.0mm |
| 그리퍼 최대 개구폭 (ctrl=+1.5) | 53.7mm |
| 닫힘 (ctrl=-1.5) | 19.2mm |

→ 큐브를 물려면 **편당 1.85mm** 안에 들어와야 함. 방향까지 맞아야 해서 초정밀.
IK로 위치만 맞춰 닫아도 0/5 (최고 8.7mm 들림) — 공차가 너무 빡빡.

### (c) 단, 팔은 큐브에 도달 가능 (해법 경로)
5-DOF damped-least-squares IK (`mujoco.mj_jacSite`)로 gripperframe를 큐브에 **<1mm 정밀 도달** 확인
(중앙·오프셋·여러 높이 전부). 즉 reach는 됨 — 문제는 grasp 공차와 expert 설계.

## 3. 정상화 계획 (Phase 2 전제조건 → 7월 미루지 않고 선행)

1. **큐브 축소 50→~30mm**: 53.7mm 그리퍼에 여유 확보 (실제 타깃 PCB 부품도 소형이라 현실적).
2. **방향제어 IK expert**: 탑다운 접근 + 손가락 정렬로 cube-aware 그립. expert가 >90% 잡을 때까지 튜닝.
3. **정상 데이터 재생성**: cube-aware expert로 300ep (성공 시연 포함 + 위치 다양성).
4. **재학습**: ACT 재학습 (과적합 억제 위해 epoch 축소).
5. **측정·반복**: `render_act_rollout.py` 로 성공률 측정, 미달 시 데이터/랜덤화/하이퍼파라미터 조정 후 재학습.

예상 소요 ~5~8일 (엔지니어링 1~2일 + 백그라운드 컴퓨트 재학습 사이클). Phase 2(7월 Sim2Real) 출발 전 완료 목표.
