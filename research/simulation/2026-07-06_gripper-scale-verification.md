# 그리퍼/치수 검증 — "기기가 작아서 3~5cm 박스를 못 잡는 것 아닌가?" (2026-07-06)

## 결론: 의심 기각 — 하드웨어 크기 문제 아님. 영상은 렌더 착시.

| 항목 | 수치 | 근거 |
|---|---|---|
| 시뮬 큐브 | **30mm** 한 변 | `scene_grasp_pads.xml:29` geom size 0.015(half-extent, m) |
| 그리퍼 손끝 최대 개구 | **94.5mm** (qpos=1.23) | `_gripper_opening_measure.py` 재실행 실측. 6/22 "53.7mm"는 오측(ctrl ±1.5만 스윕 + geom AABB 중심 간격), 6/23 정정치가 맞음 |
| 운영 씬 평행 패드 개구 | **70.0mm** @qpos 1.5(GRIP_OPEN), 최대 71.7mm | 신규 probe (scene_grasp_pads 로드) |
| 시뮬↔실물 스케일 | **1:1 일치** | MJCF = onshape-to-robot 공식 CAD 수출(scale 속성 없음, 미터 단위). STS3215 서보 메시 폭 24.8mm vs 실물 스펙 24.7mm 일치. upper_arm 116.0mm / lower_arm 135.0mm |
| 실물 교차 검증 | 실물 SO-ARM101 이 텔레오퍼레이션으로 3~5cm 물체 파지 성공 | 6/23 기록 (closed-loop-grasp-cron-handoff.md:13) |

- **3cm 박스** = 손끝 개구의 32% (여유 편당 32mm), 패드 개구의 43% → 충분.
- **5cm 박스** = 손끝 개구의 53% (여유 22mm), 패드 개구의 71% → 기하적으로 가능.
- 과거 0% 실패의 원인은 크기·토크·공차가 아니라 **open-loop 제어 + TCP/IK 정렬** — closed-loop 로 해결됨(88%/70%).

## 영상에서 작아 보이는 이유 (착시 메커니즘)
`overhead_camera` = 높이 1m 고정, fovy 기본 45°, 640×480. 큐브 상면(z≈0.19m)까지 0.81m →
세로 시야 671mm/480px = **1.40mm/px** → 30mm 큐브가 화면에서 **~21px**.
팔 전체(리치 ~415mm)가 프레임을 지배하고 스케일 기준물이 없어 기기·물체가 실제보다 작아 보인다.
**모델 치수 문제가 아니라 탑다운 원거리 렌더의 특성.** (보고용 영상에는 사선 앵글/클로즈업 카메라 추가 권장.)

## 단서 조항 — "30mm 학습 정책이 50mm 를 잡는가"는 별개 문제
현 정책·expert 는 30mm 전용 상수로 동작:
- `APPROACH_GRIP=0.45` → 접근 시 패드 갭 ~38mm < 50mm → **50mm 큐브는 접근 자세에서 이미 충돌**
- `CLOSE_Q=0.13` = 30mm 점진 닫힘 종료점

50mm 커버 절차(Phase 2 후속): ① 큐브 크기 랜덤화(25~50mm)를 DR 축에 추가,
② `APPROACH_GRIP≥0.95`(갭 ~57mm)·`CLOSE_Q≈0.7`(갭 ~48mm) 재튜닝, ③ 재수집→재학습→재측정.
현행 7/7 마감 DR 재학습(조명/마찰/카메라)에는 크기 축이 없음을 인지할 것.
