## 1. 측정

### (a) 스톡 그리퍼 실제 개구폭 (정정 결과)

`scripts/_gripper_opening_measure.py` — 손가락 끝 그립밴드(gripper z ∈ [-0.105,-0.060]) 안쪽면 측정:

| 항목 | 값 |
|---|---|
| 최대 개구 | **94.5mm** (gripper qpos=1.23) |
| 닫힘 | -21.6mm (음수: 두 손가락 안쪽면이 교차) |
| 50mm 큐브 점유 | 53% (편당 여유 22.2mm) |
| 30mm 큐브 점유 | 32% (편당 여유 32.2mm) |
| 안정 그립 권장 ≤ 70% | 물체폭 ≤ **66mm** |

→ 6/22 보고서가 인용한 "최대 53.7mm" 는 **틀린 TCP 측정값**이었다. 정정: 50mm 큐브는
공차 측면에선 충분히 잡을 수 있는 크기. 1차 결함은 공차가 아니라 **closure 동역학**.

### (b) 세 가지 grasp 전략 재실행 결과

| 스크립트 | 시나리오 | FORCE | 성공률 | 핵심 진단 |
|---|---|---|---|---|
| `_grasp_pedestal_test.py` | 50mm 큐브 + 작업대 z=0.16 + jaw중점 TCP + 탑다운 IK | 0(스톡 1.5) | **0/8 (0%)** | IK 오차 0.5mm — 도달 완벽. lift 0mm → close 후 큐브 슬립 |
| `_grasp_pads_test.py` | 50mm 큐브 + 패드모델 + APPROACH=0.4, CLOSE=-0.5, GRASP_DZ=0 | 6.0Nm | **0/8 (0%)** | 8개 중 1개만 closure 접촉 3개 발생, 나머지 접촉=0 |
| `_grasp_small_test.py` | **12mm 큐브** (3.2g) + 패드모델 + FORCE=6.0 | 6.0Nm | **0/8 (0%)** | 접촉 0, max_lift 0~5mm — 손가락이 작은 큐브를 비껴감 |

→ **공차/토크/물체크기를 다 풀어줘도 closure가 안 됨**. 진짜 벽은 **그리퍼 충돌 모델 자체**.

## 2. 원인 분석

스톡 SO-101 그리퍼 (`so101_new_calib.xml`) 구조:
- **단일 revolute 조인트** (`gripper` joint) — 회전식 1자유도. 가동 손가락(`moving_jaw_so101_v1`)이
  핀(pivot) 둘레로 호(arc)를 그리며 닫힘. **평행 이동이 아니다.**
- **풀 메시 충돌** — 손가락이 STL 메시 그대로 콜리전. 정밀 그립면이 없고, 가장자리·돌출부가
  먼저 충돌해 자유물체를 밀쳐낸다.
- **자유 큐브** (cube_joint = free) — 콜리전 0접촉 자세에서 작은 측면 충격에도 큐브가 슬립.

→ 호운동 손가락이 큐브를 측면에서 치면, 자유물체 큐브가 미끄러져 빠져나간다.
정확히 메모리에 기록된 "closure는 그리퍼 충돌모델(풀메시) 문제로 좁혀짐"의 측정 증거다.

## 3. 결정

**스톡 단일 revolute 조 → 평행조(parallel jaw) 그리퍼로 교체**.
메모리 기록 *grasp-sim-strategy-2026-06.md* 의 방침("평행조 채택") 확정.

### 평행조 채택 근거
- 일반 산업 그리퍼 표준 (Robotiq 2F-85, Franka Hand 등)
- 두 손가락이 평행 이동 → 자유물체에 측면 슬립 없이 핀치
- 콜리전: 단순 박스 패드(저폴리) → 안정적 정접촉
- Sim2Real에서도 SO-ARM 실기 그리퍼를 평행조로 교체하거나, 평행조 학습 모델을
  실기 단일조에 fine-tune 하는 두 경로 가능. (실기 통합은 Phase 2 안건)
